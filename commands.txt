manage-system — commands for the presentation
=============================================

All commands assume you are in the project folder:

    cd /home/thewanderer/manage-system

This machine has real Docker now (not Podman). Do NOT set DOCKER_HOST.
If you get "permission denied" on the docker socket, run this once in the
terminal:

    newgrp docker

.env is already in the project folder. You do not need to copy it again.


1. Open the app (no tests)
--------------------------

    docker compose up -d
    docker compose exec web flask db upgrade

(Use "docker compose up -d --build" only if you changed code.)

Then open:

    App          http://localhost:5000
    API docs     http://localhost:5000/docs
    Health       http://localhost:5000/health
    Keycloak     http://localhost:8080
    Grafana      http://localhost:3000
    Prometheus   http://localhost:9090

Keycloak's first start can take a minute. Wait until
http://localhost:8080 answers before you sign in.

Sign in from the app with "Continuar con Keycloak".

    alice_worker   password123
        Employee. Dashboard, products, and stock.
        Reports, audit, and users stay hidden.

    kratos_boss    password123
        Manager. Add a product, reject a duplicate SKU, record a
        stock exit, then open reports, audit, and users.

Suggested order in the room:

    1. Sign in as alice_worker.
    2. Show the dashboard, search products, record a stock entry.
    3. Sign out.
    4. Sign in as kratos_boss.
    5. Add a product, try the same SKU again, record an exit.
    6. Open reports, audit, and users.
    7. Open /docs and Grafana if you want the API and dashboards.

Stop the app when you are done. The database volume is kept.

    docker compose down


2. Tests
--------

The normal app can stay up for a quick service check.
The full suite and staging use ports 5000, 8080, and 5432,
so stop the app first if you run those:

    docker compose down

Full suite. Unit tests, contract tests, migrations, coverage,
dependency audit, Playwright, observability stack, and a short
k6 smoke test. Reports are written to reports/. Open
reports/index.html when it finishes.

    bash scripts/run-full-test-suite.sh

Same suite without the browser tests and without the full stack:

    RUN_E2E=false RUN_STACK=false bash scripts/run-full-test-suite.sh

App is already up, and you only want to show that every service
answers (Flask, Keycloak, Prometheus, Grafana, Loki, Tempo,
Alertmanager, Alloy, and an authenticated API call):

    bash scripts/verify-stack.sh


3. Individual tests
-------------------

Unit and contract tests do not need the app running.
Browser tests, k6, and verify-stack.sh do. Leave
"docker compose up" running for those.

Products, stock, and users:

    pytest tests/test_products.py tests/test_stock.py tests/test_users.py -v

One file, or one test inside a file:

    pytest tests/test_products.py -v
    pytest tests/test_products.py::TestProductCRUD::test_create_and_get_product -v

API contract (Schemathesis):

    pytest tests/test_contract.py -v

Migrations and the duplicate-SKU rule. These need Postgres.
With the demo stack already up, point them at that database:

    export FLASK_APP=app.main
    export DATABASE_URL=postgresql://postgres:your_password_here@localhost:5432/inventory_db
    flask db upgrade
    pytest tests/data/ -v

Browser tests. The app from "docker compose up" has to be running.

    export E2E_BASE_URL=http://localhost:5000
    export E2E_ALICE_USER=alice_worker
    export E2E_ALICE_PASSWORD=password123
    export E2E_MANAGER_USER=kratos_boss
    export E2E_MANAGER_PASSWORD=password123
    pytest tests/e2e/test_auth.py -m e2e -v

The other browser files are tests/e2e/test_products.py,
tests/e2e/test_stock.py, and tests/e2e/test_audit.py.
All four at once:

    pytest tests/e2e -m e2e -v

Load smoke. The app must be up.

    docker run --rm --network host -v "$PWD:/app" -w /app \
      -e BASE_URL=http://localhost:5000 \
      -e KEYCLOAK_URL=http://localhost:8080 \
      grafana/k6:0.53.0 run tests/k6/smoke-test.js

tests/k6/load-test.js is the 50-user products test.
tests/k6/stress-test.js is the stock-movement stress test.

Do not run the full suite or staging while this app is up.
Both need ports 5000, 8080, and 5432, and the full suite
stops whatever is already using them.


4. Staging
----------

Same app, but from the built image, with Gunicorn, health checks,
and Keycloak in its own database. Stop the normal stack first.
Staging uses the same host ports.

    docker compose down
    bash scripts/run-staging-qa.sh

That starts staging, runs the 4 browser tests against
http://localhost:5000, and writes the OWASP ZAP report to:

    security-reports/staging-zap-baseline.html

Start staging without the tests:

    docker compose -f docker-compose.staging.yml -p manage-system-staging up -d --build

Stop staging:

    docker compose -f docker-compose.staging.yml -p manage-system-staging down


5. Jenkins
----------

Only if you want the pipeline on screen. The app does not need
to be running.

    docker compose --profile jenkins up -d --build jenkins

Open http://localhost:8090 and run the job named manage-system.
It reads the Jenkinsfile and runs the same stages as the full
test script: build, unit, API, migrations, coverage, security,
Playwright, full stack plus k6, and a final Docker image.

Stop Jenkins:

    docker compose --profile jenkins down


6. What you do not run by hand
------------------------------

GitHub Actions runs by itself on a push or pull request to main
or dev. It builds, then runs unit tests, contract tests, migration
tests, coverage, Playwright, the dependency audit, and a Docker
image build. It does not start Grafana or k6. That extra stage is
only in:

    bash scripts/run-full-test-suite.sh

and in the Jenkins job.


7. SonarQube (local, optional)
------------------------------

Separate from the app stack. Does not touch its data.

    docker compose -f docker-compose.sonar.yml -p manage-system-sonar up -d

Wait about 2 minutes, open http://localhost:9000 (admin / admin, then
change the password). Create a project with key "manage-system", then
My Account > Security > generate a token. Then:

    export SONAR_TOKEN=<your token>
    bash scripts/run-sonar-scan.sh

Results: http://localhost:9000/dashboard?id=manage-system

Stop it (keeps its data):

    docker compose -f docker-compose.sonar.yml -p manage-system-sonar down


8. Python coverage (local)
--------------------------

Report from the last full test run:

    xdg-open reports/htmlcov/index.html

Regenerate it. Needs Postgres, so use the full suite instead:

    RUN_E2E=false RUN_STACK=false bash scripts/run-full-test-suite.sh

(This wipes the app database. Do not run it before the presentation.)

Quick coverage without a database (unit + contract tests only, in Docker):

    docker run --rm -v "$PWD:/app" -w /app -e PYTHONPATH=/app -e FLASK_APP=app.main \
      python:3.12-slim bash -lc "pip install -q -r requirements.txt && \
      pytest tests/test_products.py tests/test_stock.py tests/test_contract.py \
      --cov=app --cov-report=term-missing --cov-report=html:htmlcov -q"

Then open htmlcov/index.html. Or print the total from the existing XML:

    python3 -c "import xml.etree.ElementTree as E;print(round(float(E.parse('reports/coverage.xml').getroot().get('line-rate'))*100,1),'%')"


Fast coverage with no database and no Docker (unit, API, UI and auth tests,
about 98% of app/). From the project folder:

    python3 -m venv /tmp/venv && /tmp/venv/bin/pip install -q -r requirements.txt
    DATABASE_URL=sqlite:///:memory: /tmp/venv/bin/pytest tests/ -m "not e2e" \
      --ignore=tests/e2e --ignore=tests/data --cov=app --cov-report=term-missing \
      --cov-report=html:htmlcov -q

New test files: tests/test_ui_routes.py, tests/test_keycloak_admin.py,
tests/test_auth_security.py, tests/test_api_edge_cases.py.


9. Prepare before presenting (do this 1 hour before)
----------------------------------------------------

Tonight: commit and push everything.

    git add -A && git commit -m "Fix observability stack, add code reference" && git push

Never use "docker compose down -v" or scripts/run-full-test-suite.sh
before presenting: both delete the users and data.

Start the stack and check it:

    docker compose up -d
    docker compose exec web flask db upgrade
    bash scripts/verify-stack.sh

If login fails (users missing), restore them:

    bash scripts/prepare-keycloak-e2e.sh

Generate data so every Grafana panel has something to show:

  1. Open http://localhost:5000 and sign in as kratos_boss / password123.
  2. Create a product, then make a few stock movements (entries and
     exits). Repeat them a minute later: rate and increase panels need
     two Prometheus scrapes (about 30 seconds) to show values.
  3. Click around the app for a minute or two to build traffic.
  4. Security panels and alerts (30 bad-token requests from one IP):

        for i in $(seq 1 30); do curl -s -o /dev/null -H "Authorization: Bearer bad" localhost:5000/api/products; done

     This raises SpikeInvalidTokens and AuthFailuresFromSingleIP in
     Alertmanager (they clear on their own after a few minutes).

  5. Failed logins (wrong password on the Keycloak login page, 6+ times,
     or with curl). Wait about a minute: the Security dashboard shows
     "Logins fallidos en Keycloak" and the KeycloakFailedLogins alert fires.

        for i in $(seq 1 8); do curl -s -o /dev/null -d grant_type=password -d client_id=flask-backend -d username=kratos_boss -d password=WRONG http://localhost:8080/realms/inventory-realm/protocol/openid-connect/token; done

Tabs to have open:

    App            http://localhost:5000    kratos_boss / password123
    Grafana        http://localhost:3000    admin / admin
                   (folder "Observability": 4 dashboards)
    Prometheus     http://localhost:9090    Status > Targets (7 up), Alerts
    Alertmanager   http://localhost:9093
    Keycloak       http://localhost:8080    admin / admin

Logs and traces (Grafana > Explore):

    Loki   {container="flask_app"}     click "View Trace" on a line to open Tempo

If a panel looks empty: wait about 30 seconds and send more traffic. After a
restart the rate-based panels show 0 until two scrapes have happened.


10. Presentation day (quick reference)
--------------------------------------

Everything is stopped and the data is kept. Never use "down -v" or
the full test suite before presenting: both delete the users and data.

Start (about 15 minutes before):

    cd ~/manage-system
    newgrp docker                       # only if "permission denied"
    docker compose up -d
    docker compose exec web flask db upgrade

Wait about 30 seconds, then check Keycloak answers (expect 200):

    curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080/realms/inventory-realm

Quick health check of every service (optional):

    bash scripts/verify-stack.sh

Logins:

    Keycloak admin   http://localhost:8080   admin / admin
    kratos_boss      password123 (manager)
    alice_worker     password123 (employee)

Warm-up: sign in once as kratos_boss, then sign out.

Show coverage (98% of app/):

    xdg-open htmlcov/index.html

Stop at the end (keeps the data):

    docker compose down


11. Public demo URL (Cloudflare tunnel, free, no account)
---------------------------------------------------------

Gives the app, Keycloak and Grafana random https://*.trycloudflare.com
addresses. localhost keeps working. The stack must be up first.

    docker compose up -d
    bash scripts/cloudflare-tunnel.sh           # prints the public URLs
    bash scripts/cloudflare-tunnel.sh status    # show them again

Open the "App (share this)" URL and log in as kratos_boss / password123.

The URLs change every time you start it. They only work while this PC is
on, awake and online. Keep the terminal you started it in open.

WARNING: it also exposes the Keycloak admin console (admin / admin) to
anyone who has the link. Do not post the URLs publicly. Always stop it
when you are done:

    bash scripts/cloudflare-tunnel.sh stop

That removes the tunnels and puts Keycloak back to localhost only.
Check nothing is left running:

    pgrep -a cloudflared      # should print nothing


12. Turn everything off
-----------------------

    bash scripts/cloudflare-tunnel.sh stop      # only if a tunnel is running
    docker compose down                         # keeps the data

Optional extras, only if you started them:

    docker compose -f docker-compose.sonar.yml -p manage-system-sonar down
    docker compose --profile jenkins down
